---
name: 목업 우선 원칙
description: 새 기능은 목업 스프린트(mock 데이터)로 UI/UX 확인 후 구현 스프린트를 진행한다
type: feedback
---

요구사항은 언제든 변경될 수 있으므로, 백엔드/DB 변경이 조기에 일어나는 것을 방지해야 한다.

**규칙: 목업 먼저, 구현은 나중에**

1. 새 기능 → 목업 스프린트(프론트엔드 전용, mock 데이터, DB/백엔드 변경 없음)
2. 목업 검토 + 요구사항 확정
3. 구현 스프린트(DB 마이그레이션, 백엔드 API, 프론트 연동)

**Why:** 요구사항 정리가 여러 번 일어날 수 있는 초기 단계에서 DB 스키마를 미리 확정하면 마이그레이션 롤백이나 데이터 손실 위험이 생긴다. 프론트엔드 목업은 언제든 수정/롤백 가능하다.

**How to apply:**
- 목업 스프린트 문서에는 반드시 "목업" 유형 명시
- mock 데이터 파일은 `frontend/src/mocks/` 디렉토리에 위치
- mock 파일에는 `// Sprint N에서 실제 API로 교체` 주석 포함
- 구현 스프린트 문서에는 "선행 조건: 목업 완료 + 요구사항 확정" 명시

**예외: 버그 수정은 목업 생략 가능**
- 파일 3개 이하, 코드 50줄 이하, DB 변경 없음 → 바로 수정
